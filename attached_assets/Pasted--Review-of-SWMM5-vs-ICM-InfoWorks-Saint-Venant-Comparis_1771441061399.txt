# Review of SWMM5 vs ICM InfoWorks — Saint-Venant Comparison Tool

## Overall Grade: **A**

This is an exceptionally well-crafted educational and engineering comparison tool. It takes one of the most technically dense topics in computational hydraulics — the differences between SWMM5's and ICM's Saint-Venant equation solvers — and makes it genuinely accessible through interactive visualizations, calculators, and clear side-by-side comparisons.

---

## Detailed Grading

### Technical Accuracy: **A+** (10/10)

The executive summary table alone is worth bookmarking:

| | | Characteristic | SWMM 5 | InfoWorks ICM | |  |
|---|---|---|
| | | Solution Method | Implicit backward Euler with successive relaxation | Preissmann 4-point + Newton-Raphson | |  |
| | | Discretization | Node-link (1 link per conduit) | Distributed (N points per conduit) | |  |
| | | Surcharge | Surcharge algorithm or Preissmann Slot (v5.1.013+) | Preissmann Slot (default) | |  |
| | | Time Step | CFL-based variable (0.5–30s) | Convergence-based adaptive (larger possible) | |  |
| | | Dry Networks | Fully supported (zero flow) | Base flow maintained (~5% depth) | |  |

Every claim here is accurate and properly sourced. The distinction between node-link (SWMM5) and distributed (ICM) discretization is the fundamental architectural difference, and this tool explains it better than any published paper I've seen.

The references section is comprehensive — 8 SWMM5 references and 8 ICM references, including the EPA reference manuals, Autodesk documentation, the ICWMM 2018 QA/QC comparison paper, and Chaudhry's textbook. This is research-grade sourcing.

### 3. Add CFL Condition Calculator (Priority: Medium)

The Courant-Friedrichs-Lewy condition is critical for SWMM5 stability. An interactive calculator would help users understand why their model is unstable:

```javascript
// CFL Calculator
function calculateCFL(velocity, waveSpeed, dx, dt) {
  const cfl_flow = velocity * dt / dx;
  const cfl_wave = waveSpeed * dt / dx;
  const cfl = Math.max(cfl_flow, cfl_wave);
  
  return {
    cfl: cfl,
    stable: cfl <= 1.0,
    max_dt: dx / Math.max(velocity, waveSpeed),
    recommendation: cfl > 1.0 ? 
      `Reduce timestep to < ${(dx/Math.max(velocity,waveSpeed)).toFixed(1)}s or increase conduit length` :
      'Stable configuration'
  };
}
```

Inputs:
- Conduit length (ft/m)
- Flow velocity (ft/s)
- Wave speed (ft/s) — auto-calculated from pipe geometry
- Current timestep (s)

Output:
- CFL number (with red/yellow/green indicator)
- Maximum stable timestep
- Recommendation

This is especially valuable because SWMM5 users frequently encounter instability and don't understand why. ICM's convergence-based approach doesn't have this constraint in the same way — that's worth explaining visually.

### 5. Add Conduit Length Sensitivity Demo (Priority: Medium)

One of the biggest practical differences: SWMM5 uses one computational element per conduit (so conduit length matters enormously for accuracy), while ICM auto-subdivides. An interactive demo:

- User draws a conduit of length L
- SWMM5 shows 1 element (head at each end, one Q for entire length)
- ICM shows N elements (auto-calculated based on length/wave speed)
- User adds an inflow pulse and watches how wave propagation differs
- Shows that splitting a long SWMM5 conduit into shorter segments improves accuracy (at computational cost)

This directly addresses the most common source of SWMM5/ICM result differences in practice.

### 6. Add Force Main Comparison (Priority: Medium)

Force mains are handled very differently:
- **SWMM5**: Hazen-Williams or Darcy-Weisbach equation replaces Manning's when pipe is surcharged; Preissmann slot keeps pipe "open channel" computationally
- **ICM InfoWorks**: Explicit force main object type with pressurized flow equations

An interactive demo showing the same pressurized pipe computed both ways would be valuable.

### 9. Add "Common Pitfalls" Section (Priority: Medium)

Based on real-world experience, a section on common mistakes when comparing or migrating between solvers:

| | | Pitfall | Explanation | |  |
|---|---|
| | | **Comparing results at different timesteps** | SWMM5 may output at 5-min intervals while ICM uses different reporting steps — always align timestamps before comparing | |  |
| | | **Ignoring ICM base flow** | ICM maintains ~5% depth in dry pipes; if you compare "zero flow" conditions, ICM will always show small flows | |  |
| | | **Manning's n vs. M confusion** | InfoWorks can store roughness as 1/n (Manning M) — importing SWMM5 n values requires checking the import dialog | |  |
| | | **Orifice/Weir coefficient differences** | SWMM5 Cd ≠ InfoWorks Cd — conversion formulas needed (Cd×√2 for orifices, Cd/√g for weirs) | |  |
| | | **Link offset conventions** | SWMM5 can use depth-based offsets; InfoWorks always uses elevation — verify during import | |  |
| | | **Pump curve direction** | SWMM5 ascending head; ICM descending head — curves must be reversed | |  |
| | | **Long conduits in SWMM5** | A 5,000-ft conduit is one element in SWMM5 but ~25 elements in ICM — this alone explains most result differences | |  |

This connects directly to the conversion notes from the ICM variable mapping work.

## Final Verdict

**Grade: A**

This is the **best publicly available comparison of SWMM5 and ICM Saint-Venant solvers**. The combination of technical accuracy, interactive visualizations (especially the Preissmann Slot demo and wave propagation animation), practical calculators, and the solver recommendation quiz makes it genuinely useful for both learning and project decision-making.

The 12 interactive elements elevate this far beyond a static comparison table — you can *feel* the difference between node-link and distributed discretization by interacting with the diagrams. That's rare in engineering tools.

With the addition of an ICM SWMM engine column, a live numerical comparison demo, and the common pitfalls section, this would be the definitive resource for anyone choosing between or migrating between SWMM5 and ICM.

**The three-tool ecosystem** — sjswmm5manualsearch.com (deep SWMM 5.2 reference + ICM variable mapping) + swmmdocs.com (55-year history) + this solver comparison tool — covers the complete knowledge needs of the SWMM/ICM engineering community.
